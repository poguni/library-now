지금 열린 도서관 개발 보고서 (v1)

작성일: 2026-11-21버전: v1

1. 개요

항목내용
앱 이름지금 열린 도서관 (Library Now)
한 줄 소개지금 문 연 서울 공공도서관과 "지금 가면 몇 시간 이용할 수 있는지"를 지도로 보여 주는 웹앱
형태반응형 웹앱(데스크톱·태블릿·스마트폰), 홈 화면 설치(PWA), 로그인 없음
대상 사용자개발자 본인(구로구 인근에서 책을 빌리거나 공부하러 도서관을 다니는 사람), 포트폴리오 방문자
배포 주소https://poguni.github.io/library-now/
개발 기간2026-11-18 ~ 2026-11-21 (4일, 커밋 24개)
데이터 범위서울 25개 구 공공도서관 254곳 (구로구·영등포구·양천구 34곳은 홈페이지와 대조해 검수, 나머지 220곳은 공공데이터 자동 변환)

2. 목표 및 배경

도서관에 가려고 할 때 자주 겪는 불편에서 출발했습니다.

  1. 헛걸음: 휴관일이 "매주 월요일", "매월 둘째·넷째 월요일", "법정공휴일"처럼 도서관마다 다르고, 공휴일이 끼면 더 헷갈립니다.
  2. 자료실과 열람실의 시간 차이: 책을 빌리는 자료실은 18시에 닫아도 열람실은 22시까지 여는 곳이 많습니다. 목적에 따라 답이 달라집니다.
  3. 흩어진 정보: 구립·시립·교육청 도서관마다 홈페이지가 달라 한눈에 비교하기 어렵습니다.
  4. 구 경계: 경계 근처에 살면 다른 구의 도서관이 더 가까울 수 있습니다.

핵심 가치는 "앱을 열고 3초 안에 지금 갈 수 있는 도서관을 아는 것"입니다. 단순히 "운영 중"을 보여 주는 데서 그치지 않고, 출발지에서 도착할 시각을 추정해 "지금 가면 ○시간 ○분 이용 가능"을 계산하는 것이 이 앱만의 특징입니다. 비용은 0원으로 유지합니다(서버·DB·유료 API 없음).

3. 주요 기능

지도와 상태

  • 도서관 지도: 상태별 색·기호·글자를 함께 쓴 마커, 확대 단계에 따른 이름표, 가까운 마커 묶기(숫자 배지)
  • 운영 상태 배지: 운영 중 ●, 곧 닫힘 ◔, 곧 열림 ◐, 운영 종료 ○, 휴관 ✕, 운영시간 확인 필요
  • 이용 모드: 책 빌리기(자료실) / 공부하기(열람실)를 나눠 판단
  • 지도 종류 선택: OpenStreetMap(기본) 또는 카카오맵(설정에서 선택, 불러오지 못하면 기본 지도로 전환)

지금 가면 몇 시간

  • 출발지: 현재 위치, 집, 직장(지도에서 지정, 브라우저에만 저장)
  • 거리와 이동 시간 추정(직선거리 × 우회 계수, 도보·대중교통 구분, "추정" 표기)
  • 도착 시각 기준 남은 이용 시간, 도착하면 마감이면 다음 개관 안내
  • 기준 시각 바꾸기: 다른 날짜·시각을 골라 그때 기준으로 다시 계산

찾고 비교하기

  • 목록: 이름 검색(띄어쓰기 무시), 필터(전체·지금 열린 곳만·즐겨찾기·검수된 곳만), 정렬(거리·남은 시간·이름)
  • 지역 선택: 25개 구를 패널에서 켜고 끄기
  • 휴관일 달력: 즐겨찾기 도서관의 휴관일을 색 점으로 겹쳐 보기, 즐겨찾기가 없으면 날짜별 문 여는 곳 수
  • 도서관 상세: 요일별 운영시간 표(자료실·열람실), 정기 휴관 규칙과 원문, 미니 달력, 데이터 출처·기준일

이동과 공유

  • 길찾기: 카카오맵·네이버 지도로 넘기는 링크, 주소 복사
  • 링크 공유: 선택한 도서관과 이용 모드를 주소에 담아 공유(위치·출발지는 담지 않음)
  • 소장 도서 검색: 검수된 34곳은 확인한 자료 검색 페이지로, 나머지는 홈페이지로 연결하는 카드

개인화와 편의

  • 즐겨찾기, 내 메모, 임시 휴관 직접 입력(상태·달력 계산에 반영)
  • 화면 테마 3종: 서재(기본)·말랑·모노
  • 글자 크기 3단계(보통·크게·아주 크게), 아이콘 버튼 툴팁
  • 내 데이터 내보내기·가져오기(JSON), 초기화
  • 홈 화면 설치와 오프라인 보기(도서관 데이터는 저장, 지도 타일은 정책상 저장하지 않음)

구조

앱은 실행 중에 외부 API를 부르지 않는 정적 방식입니다. 데이터는 빌드할 때 한 번 만들고, 앱은 public/data/*.json만 읽습니다.

data/raw/        공공데이터 원본 CSV (수정 금지)
data/overrides/  검수한 34곳의 자료실·열람실 시간과 휴관 규칙
data/holidays/   연도별 공휴일 수기 정리 (2026, 2027)
      │  npm run data:build  (auto.ts 자동 변환 → merge.ts 병합 → validate.ts 검증)
      ▼
public/data/     libraries.json (254곳, 약 270KB), meta.json, holidays.json
      │
      ▼
src/domain/      시간 계산·휴관 판정·이동 시간 추정 (순수 함수 + 테스트)
src/map/         MapProvider 인터페이스, Leaflet 구현, 카카오맵 구현, 마커 묶기
src/state/       설정·즐겨찾기·출발지·메모·테마·글자 크기 저장 (localStorage)
src/components/  상단 바, 목록, 지도, 상세, 달력, 설정, 바텀 시트 등
  • 모든 시간 계산은 기기 시간대와 상관없이 Asia/Seoul 기준입니다.
  • 상태 판정 순서: 임시 휴관 → 정기 휴관 → 공휴일 → 요일·계절별 운영시간.
  • 데스크톱(1200px 이상)은 목록·지도·상세 3단, 태블릿은 접히는 패널, 스마트폰은 바텀 시트와 아래 탭 바를 씁니다.

6. 주요 의사결정과 이유

결정이유
서버·DB 없는 정적 방식비용 0원, 개인 사용, GitHub Pages만으로 배포. 데이터는 빌드 때 JSON으로 만듦
자료실과 열람실을 항상 따로 계산"책 빌리기"와 "공부하기"의 답이 다르기 때문. 열람실이 없으면 비워 둠
운영시간을 추측해서 채우지 않음틀린 값은 헛걸음으로 이어짐. 해석하지 못한 값은 "운영시간 확인 필요"로 표시
25개 구를 한 번에 넣고 "미검수" 표시220곳을 모두 홈페이지와 대조하려면 시간이 오래 걸림. 범위는 먼저 넓히고 검수는 구 단위로 천천히
공휴일은 API 대신 수기 JSON키 발급과 실행 중 API 호출을 피함. 연 1회 정리로 충분
이동 시간은 직선거리 기반 추정경로 API는 키·비용이 듦. "추정"으로 표기하고 정확한 경로는 외부 지도 앱으로 넘김
Leaflet을 react-leaflet 없이 직접 사용카카오맵과 같은 MapProvider 인터페이스 뒤에 두기 쉬움
카카오맵은 선택 사항키가 없거나 불러오지 못해도 OSM으로 동작하게 해 장애에 강하게 함
책 검색은 링크 방식도서관 정보나루 API는 키와 서버 중계가 필요해 정적 방식과 맞지 않음. 먼저 도서관 검색 페이지로 연결
기본 지도 중심은 신도림역 부근구로·영등포·양천 세 구의 가운데. 집 좌표는 Public 저장소에 넣지 않음
'21시 이후' 필터 제거필터 줄이 길어지고, 남은 시간순 정렬로 같은 목적을 이룰 수 있음
커밋은 사용자가 직접개발 과정을 사용자가 확인하며 기록을 관리하기 위함

7. 문제 해결 기록

공공데이터의 운영시간 형식이 제각각

  • 문제: 자동 변환한 220곳 중 휴관일 문장("매월첫째셋째월요일+정부지정공휴일", "월(격주)+일(2·4주)")과 "00:00~00:00" 같은 빈 시간이 섞여 있었습니다.
  • 해결: 해석할 수 있는 규칙만 변환하고, 해석하지 못한 22곳은 "확인 필요"로 비워 두었습니다. 빌드할 때마다 data/auto-review.md에 검수 목록과 사유를 자동으로 남깁니다.

카카오맵에는 Leaflet의 마커 묶기를 쓸 수 없음

  • 문제: leaflet.markercluster는 Leaflet 전용이라 카카오맵에서는 마커가 겹쳤습니다.
  • 해결: 화면 좌표 기준으로 가까운 마커를 묶는 함수(groupPoints)를 따로 만들고 단위 테스트를 붙였습니다. 고른 도서관은 묶음에서 빼서 늘 보이게 했습니다.

테마 필터가 카카오맵 타일에만 걸리게 하기

  • 문제: 테마별 지도 색 필터를 카카오맵 전체에 걸면 마커와 팝업까지 색이 바뀌었습니다.
  • 해결: 타일 이미지만 고르는 선택자(.ln-kakao img[src*='/api/v1/tile/'])에 필터를 적용했습니다.

큰 글자에서 화면이 깨짐

  • 문제: 글자 크기를 키우자 긴 도서관 이름, 카드 장식, 길찾기 버튼이 넘쳤습니다.
  • 해결: 이름 줄바꿈을 허용하고 버튼 높이를 글자에 맞춰 늘렸으며, 테마 장식이 크기·배치를 바꾸지 않도록 정리했습니다.

스마트폰 상단 바에 빈 줄이 생김

  • 문제: 390px 폭에서 "지금 · 11월 21일(토) 10:29" 칩이 길어 글자 크기 버튼이 혼자 다음 줄로 내려가 상단 바가 약 200px가 되었습니다.
  • 해결: 스마트폰에서는 시각을 "11.21 10:29"로 줄이고 앱 이름 크기를 고정했습니다. 상단 바가 보통·크게에서 159px, 아주 크게에서 203px로 줄었습니다(기존 201px·250px).

개발 환경 문제

  • 전날 켜 둔 개발 서버가 5173 포트를 차지해 새 서버가 뜨지 않은 일이 있어, 확인 뒤 정리했습니다.
  • 공공데이터 사이트 접속이 막히는 경우를 대비해 원본 CSV를 직접 내려받아 data/raw/에 두는 방식으로 정했습니다.

8. 보안/성능 고려사항

  • 개인정보: 위치와 집·직장 좌표는 브라우저에만 저장하고 밖으로 보내지 않습니다. 예외는 사용자가 길찾기 링크를 누를 때뿐입니다. 공유 링크에도 위치는 담지 않습니다.
  • 키 관리: 카카오맵 JavaScript 키는 .env(git 제외)와 GitHub Actions 비밀 값으로만 다룹니다. 키가 없으면 카카오맵 선택지를 숨깁니다.
  • 저장 실패 대비: localStorage 읽기·쓰기를 모두 try/catch로 감싸 저장이 막힌 브라우저에서도 앱이 동작합니다. 저장 형식에는 버전 번호를 둡니다.
  • 지도 타일 정책: OSM 출처를 표기하고, 서비스 워커에서 지도 타일을 저장하지 않습니다. 카카오맵 SDK·타일도 저장하지 않습니다.
  • 성능: 도서관 데이터는 254곳 약 270KB로 목표(서울 전체 500KB 이하) 안에 있습니다. 카카오맵 SDK는 사용자가 고를 때만 불러옵니다.

11. 알려진 한계

  • 미검수 220곳: 22개 구 도서관은 공공데이터 값뿐이라 실제와 다를 수 있고 자료실·열람실 구분이 없습니다. 22곳은 운영시간을 알 수 없어 "확인 필요"로 표시됩니다.
  • 임시 휴관: 공사·행사·시험 기간 연장 운영은 데이터에 없습니다. 홈페이지 공지를 확인하거나 직접 입력해야 합니다.
  • 이동 시간은 추정값입니다. 실제 대중교통 경로와 다를 수 있습니다.
  • 실제 기기 확인 남음: 길찾기 링크의 대중교통 탭, 공유 창, 홈 화면 설치를 PC·Android·iPhone에서 아직 확인하지 못했습니다.
  • 데이터 라이선스 칸: 전국도서관표준데이터의 이용 조건(공공누리 유형)을 확인하지 못해 meta.json의 라이선스 칸이 비어 있습니다.
  • 미구현 기능: 내 주변 반경 보기, 주말 운영 필터, 키보드 단축키, 구 경계선, 다크 모드.

12. 향후 개선 아이디어 / 업데이트 계획

다음 업데이트: 도서 통합 검색

책 제목을 한 번 입력하면 여러 도서관의 소장 여부를 함께 찾고, "이 책이 있고 지금 문 연 도서관"을 지도와 목록에 보여 주는 기능입니다. 지금은 도서관마다 검색 페이지로 따로 들어가야 하는데, 이를 한곳에서 끝내는 것이 목표입니다.

  1. 1단계: 구로구·영등포구·양천구 중심
    • 홈페이지를 검수한 34곳부터 시작합니다.
    • 검색 결과에 앱의 장점인 운영 상태와 "지금 가면 몇 시간"을 함께 붙여, 책이 있는 도서관 중 지금 갈 수 있는 곳을 먼저 보여 줍니다.
  2. 2단계: 서울시 통합 검색
    • 25개 구 254곳으로 넓힙니다. 미검수 도서관의 검수와 함께 진행합니다.

구현 전에 정해야 할 것:

  • 소장 정보를 어디서 가져올지: 도서관 정보나루 API는 소장 도서관 조회가 가능하지만 인증키가 필요하고, 브라우저에서 바로 부를 수 있는지(CORS)와 하루 호출 한도를 확인해야 합니다.
  • 정적 방식 원칙과의 관계: 키를 공개 저장소·브라우저에 드러내지 않으려면 작은 중계 서버(서버리스 함수)가 필요할 수 있습니다. 이 경우 "서버 없음" 원칙을 바꿀지 결정이 필요합니다.
  • 서버 없이 가는 대안: 검색어를 넣은 상태로 각 도서관(또는 구별 통합 도서관)의 검색 페이지를 여는 방식. 각 검색 페이지가 주소에 검색어를 받는지 확인이 필요합니다.
  • 화면 위치: 상단 바의 검색 진입점, 결과를 목록 필터("이 책이 있는 곳")로 보여 줄지 별도 화면으로 보여 줄지.

다음에 하면 좋을 것

  • 미검수 220곳 홈페이지 대조: 구 단위로 차례로 검수하고 overrides로 옮기기. "확인 필요" 22곳부터 우선
  • 실제 기기 확인: 길찾기 링크, 공유 창, 홈 화면 설치를 PC·Android·iPhone에서 확인
  • 데이터 라이선스(공공누리 유형) 확인 후 meta.json과 설정 화면 출처에 표기
  • 2027년 이후 공휴일 JSON 추가와 데이터 월 1회 갱신 절차 정리

여유가 있으면

  • 다크 모드(테마 3종 각각의 어두운 버전)
  • 주말 운영 필터, "내 주변 반경" 보기
  • 구 경계선 표시
  • 키보드 단축키(목록 이동, 모드 전환)
  • '아주 크게' 글자에서 스마트폰 상단 바의 출발·지역 칩이 두 줄이 되는 문제 정리
